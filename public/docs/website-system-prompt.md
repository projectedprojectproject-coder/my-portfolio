# 포트폴리오 웹사이트 시스템 프롬프트

> 이 문서는 이 사이트를 만들면서 제가 AI(Claude Code)에게 한 요청과 정한 규칙, 그리고 작업 중에 필수 조건으로 굳어진 것들을, 수업에서 배운 프롬프트 구조(현재 상황, 목표, 구체적인 변경, 유지할 것, 완료 기준, 결과물)에 맞춰 하나의 지시문으로 다시 정리한 것입니다. AI 도구에 기본으로 들어 있는 내부 지시는 포함하지 않았습니다.

## 1. 만든 과정

- 기간: 2026-09-09 ~ 2026-10-09
- 도구: Claude Code. 대화로 요청하면 AI가 코드 수정, 빌드, 화면 확인까지 수행했습니다.
- 방식: 큰 요청 하나로 끝내지 않고 "요청, 결과 확인, 다음 목표" 순서로 작게 이어갔습니다.
- 데이터베이스 설정(SQL)은 AI가 파일로 만들고, 제가 직접 실행한 뒤 "실행 완료, 확인해줘"라고 알리면 AI가 조회해서 확인했습니다.

## 2. 시스템 프롬프트

```text
[현재 상황]
- 성균관대학교 대학원 영상학과 석사과정 학생의 개인 포트폴리오 사이트다. 한국어 한 페이지 사이트이고 React와 Vite로 만든다.
- 소스는 GitHub 저장소의 main 브랜치에 두고 Vercel로 자동 배포한다.
- 글, 사진, 영상, 음악은 Supabase(데이터베이스, 파일 저장소, 관리자 로그인)로 관리한다.
- 섹션 순서: 헤더, 소개, 추천, 연구, 프로젝트 & 창작, 과제, 시스템 프롬프트(이 문서), 저서, 미디어, 수상 · 자격증, 변경 이력, 연락처.

[목표]
- 방문자는 코드를 몰라도 읽고 볼 수 있는 포트폴리오를 본다.
- 주인은 코드를 고치지 않고 관리자 화면에서 글, 사진, 링크, 제목을 바꾼다.
- 휴대폰에서도 같은 내용이 깨지지 않고 보인다.

[구체적인 변경]
디자인
1. 배경 전체는 빛바랜 인화지 같은 세피아 톤으로 한다. 필름 그레인, 가장자리가 어두워지는 효과, 깜빡이는 REC 점 같은 옛 필름 질감을 더하고 약간 그로테스크한 분위기를 낸다.
2. 글꼴은 빈티지하게 한다. 제목은 활판 인쇄체(IM Fell English), 본문은 Spectral, 라벨은 타자기체(Courier Prime), 한글은 Noto Serif KR을 쓴다.
3. 이미지는 세피아 톤으로 보이고 마우스를 올리면 살짝 확대된다. 헤더 사진 옆에 필름 띠 장식은 넣지 않는다.
4. 헤더는 왼쪽 글과 오른쪽 사진 구조로 하고, 사진을 헤더 전체 배경으로도 쓸 수 있게 한다.
5. 소개 아래에 사진, 글, 링크로 된 추천 카드를 둔다. 누르면 해당 섹션으로 이동한다.

관리자 화면 (/admin)
6. 이메일로 로그인한 관리자만 편집한다. 가입은 막아 두고, 일반 방문자는 읽기만 가능하다. 사이트 맨 위 이름 옆 빨간 점을 누르면 로그인 화면으로 간다.
7. 관리자 탭은 헤더, 추천, 제목, 콘텐츠, 과제, 수상·자격증, Contact, 미디어 업로드, 미디어 보기로 한다.
8. 콘텐츠는 블록으로 편집한다. 글은 여러 문단을 원문처럼 한 상자에 쓰고, 이미지는 정렬과 캡션과 클릭 링크를 지원하며, 추천 썸네일 블록과 노트 블록도 넣을 수 있다.
9. 각 섹션의 제목을 관리자에서 바꿀 수 있다.
10. 10분 동안 조작이 없으면 자동으로 로그아웃하고 경보음을 울린다.

섹션
11. 저서는 연구와 같은 카드 형태로 한다. 표지 사진과 외부 링크는 없앤다.
12. 미디어는 올린 사진, 영상, 음악을 바로 보여주고 파일 이름은 숨긴다.
13. 과제 섹션에서는 HTML 게임을 페이지 안에서 플레이하고 확대 버튼으로 키울 수 있다. 게임은 사이트와 분리된 안전한 창에서 실행한다. 과제는 관리자에서 추가하고 편집한다.
14. 변경 이력 섹션을 두고, 사이트가 바뀔 때마다 AI가 기록을 남긴다.

[유지할 것]
- 관리자가 입력한 내용이 없거나 데이터베이스에 문제가 생겨도, 방문자 화면은 코드에 적어 둔 기본 문구로 항상 정상 표시한다. (한 번 이 문제로 사이트 전체가 비어 보인 적이 있어 필수 조건으로 정했다.)
- 비밀번호와 비밀 키는 코드와 GitHub에 올리지 않는다. 브라우저에는 공개용 키만 두고, 환경변수 파일은 Git에서 제외한다.
- 관리자가 입력한 주소(링크, 게임 주소)는 안전한 형태만 화면에 쓴다.
- 기존 GitHub 기록은 덮어쓰지 않는다. 이미 기록이 있으면 먼저 설명한다.
- 휴대폰에서 화면이 가로로 밀리거나 글이 잘리지 않아야 하고, 손가락으로 누르기 좋은 크기를 쓴다.

[완료 기준]
- 린트와 빌드가 오류 없이 끝난다.
- 바꾼 화면을 직접 열어 확인하고, 데스크톱과 휴대폰 폭(375px, 320px)에서 가로 넘침이 없다.
- 데이터베이스에 SQL을 실행한 뒤에는 AI가 조회해서 실제로 들어갔는지 확인한다.
- 확인하지 못한 것(예: 로그인이 필요한 화면)은 숨기지 말고 알려준다.

[결과물]
- 코드 수정과, 필요하면 SQL 파일(supabase 폴더)을 만든다.
- 커밋 메시지는 항상 "업뎃 완료"로 한다. 푸시는 요청했을 때 main 브랜치로 하고 저장소 주소를 알려준다.
- 마지막에 바꾼 점과 직접 확인하지 못한 점을 짧게 알려준다.
- 사이트에 반영되는 변경은 변경 이력 파일(src/changelog.js)에 기록한다.
```

## 4. 알려진 한계

- 과제의 게임 파일을 새로 추가하려면 코드에 넣어야 해서 AI에게 요청해야 합니다.
- 격리된 창에서 실행하기 때문에 게임의 최고 기록은 저장되지 않습니다.
- 관리자 화면에서 직접 고친 글과 사진은 변경 이력에 기록되지 않습니다. 코드를 바꾼 것만 기록됩니다.
